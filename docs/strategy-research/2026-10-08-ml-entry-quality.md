Decision: build a leakage-controlled entry-filter experiment, but **do not fit or adopt a model on the present evidence**. No ML model was fitted, no ML parameter configuration evaluated, and no OOS outcome inspected. The target is positive expectancy on a disclosed untouched sample at stated costs; no profitable strategy is claimed or promised.

The user's request authorizes ML research, not changes to live execution or the original campaign registration. ## What the current evidence supports

The [corrected canonical training campaign](2026-10-08-accounting-correction.md) covers September 8–October 8 UTC, ten native Weltrade symbols, USD 50 per independent symbol and 1% risk. Only SFX Vol 99 executed trades, all TRENDING. The best-supported zero-fee case has 266 trades, -0.01318 mean net R and a training 95% interval spanning zero; positive-fee stress cases are negative. These 266 events are not 120,000 independent training observations. The 499 trades across alternative cost cases overlap and cannot be pooled as independent examples.

Nine symbols fail minimum-lot cash-risk/margin feasibility at these frozen assumptions. An entry filter cannot make an otherwise unaffordable lot affordable. A model must not bypass sizing, invent fractional broker lots or raise risk to generate a sample. Any different-capital experiment is a distinct preregistered research question, not a replacement baseline.

The [fee reconciliation](2026-10-08-fee-financing-reconciliation.md) balances all returned demo cashflows and corroborates current annual swap magnitudes. Zero commission is supported for observed executions on four contracts; universal historical fees and Friday/weekend financing remain unverified. Label costs must preserve that uncertainty.

[Machine-readable readiness](2026-10-08-ml-readiness.json) reports seven blocks: exact cost qualification, complete financing calendar, labels for all canonical opportunities, fresh ML holdout registration, canonical ML replay equivalence, fewer than 1,000 events and fewer than 90 calendar days. The 1,000-event/90-day floors are conservative project design choices, **not** published statistical sufficiency guarantees or grounds to ignore dependence. A model might still fail with much more data.

## First falsifiable ML hypothesis — design, not registered experiment

A small regularized model using information available at the signal close can identify low-quality canonical opportunities and increase future net-R expectancy over unchanged v2 at identical data, costs, capital and risk. Failure criterion: no positive paired expectancy difference at ordinary and doubled costs, or insufficient closed test trades, means reject without retuning.

The first model should be an interpretable **ridge net-R regressor**, not an unconstrained neural execution agent. Proposed single configuration: standardized eight causal numeric features, ridge alpha 1, intercept enabled, no feature selection, fixed seed where applicable, retain canonical signals only when predicted net R > 0. This is a design starting point, not a tuned parameter set or evaluated result. It must be frozen with concrete data dates, software versions and hashes before fitting. Constant expected-R and unchanged-v2 comparators remain mandatory. A probability-of-win classifier alone is inadequate when payoff sizes and costs differ.

Shallow boosting is a subsequent separate hypothesis only if the first registered study justifies further research. A compact sequence model (e.g. small LSTM/TCN) or locally reviewed tabular foundation model is a later comparison requiring substantially more independent events and compute/trial controls. Do not test many architectures and present only the best. Reinforcement-learning order/sizing agents, online self-modification and LLM/news-driven synthetic entries are outside this research scope.

## Labels, timing and selection bias

An event is a canonical pipeline opportunity with a unique provider/symbol/time/direction identity. Features are available only when the signal bar closes; candle opening timestamps must be advanced by one timeframe for availability. Next-bar entry gaps, realized spreads, fills, exits, MAE/MFE and net R are not entry-time features. Only prior closed-bar spread can be used, with its availability recorded. Do not equate tick count with exchange volume.

The initial feature contract is deliberately small: RSI, EMA50 distance/ATR, EMA slope/ATR, ATR/price, one- and three-bar returns/ATR, bar range/ATR, lagged spread/ATR. The implemented allowlist is a schema guard, not proof that feature computation is causal; timestamp-bound extraction and future-perturbation tests are still required. Symbol/direction/regime remain stratification metadata initially, avoiding many arbitrary encoded columns on one traded symbol.

Labels must use the corrected canonical accounting assumptions, next-bar timing and unchanged stop/target/holding rules. Record decision time, feature-available time and actual label-available time (exit bar CLOSE, not its opening timestamp). Costs and contract identity bind every label. Overlapping opportunities must remain identifiable; sample weights/dependence estimates must not treat them as independent.

Training only on the baseline's executed trades is selected data: a filter changes the open-position timeline and may expose signals the baseline previously blocked. Before fitting, canonical replay needs a reviewed opportunity/label recorder covering all relevant signal opportunities, while performance remains a complete stateful `python -m backtesting.backtest` replay. Do not simulate economic labels through a separate strategy engine, reconstruct signals from indicators, or delete risk-rejected rows without disclosure. Opportunity labels are diagnostic training inputs, never an alternative performance pipeline.

## Validation and adoption gates

1. Freeze a separate ML protocol after data/economics qualification, with exact date windows and one model configuration. Preserve the original EMA50 study and holdouts. Already inspected training remains training; neither renaming it nor splitting it again makes an untouched test.
2. Use expanding chronological training folds. Purge training events whose labels resolve at or after validation start minus embargo. Exclude evaluation labels crossing that fold's right edge. Group simultaneous symbols by time. Use actual wall-clock label end rather than assuming every 19-bar event ends in 95 minutes when gaps exist.
3. Fit all transformations on the fold's training data only. Reserve an internal chronological calibration interval if calibration is used; count this in the protocol. No random train/test shuffle, global scaling, future-filled missing values, synthetic augmentation presented as real history, or test-guided architecture/threshold choice.
4. Final evaluation occurs once only after model, feature code, costs and policy are frozen. Require at least 200 closed trades each for baseline and candidate per tested cost case, positive net expectancy, and positive lower bound of a paired symbol/day three-day block-bootstrap interval for the expectancy difference (10,000 draws; seed 20261008). These are proposed ML gates, distinct from the original campaign's 100-trade gate.
5. Report all original mission metrics: conditional/verified currency scope, net R, PF, win rate, win/loss sizes, marked drawdown, Sharpe/Sortino, exposure, MAE/MFE bounds, holding time, sample sizes, symbols, dates, gaps, trial counts and doubled spread/commission. Also report turnover, retained-signal coverage, cost break-even, calibration/forecast loss and period/symbol breakdowns. Prediction accuracy cannot substitute for trading expectancy.
6. Missing symbols or single-regime success restrict the claim. If the OOS candidate fails baseline at either cost case, reject and stop. Any new idea needs a new future holdout, not repeated testing of the failed one.

## Implemented controls versus remaining work

`research/ml_validation.py` now provides pure offline interval validation, finite numeric feature allowlisting, duplicate-event rejection, past-only expanding folds with actual-label purging and explicit fail-closed readiness. It neither imports a broker SDK nor trains, loads or executes a model. Sixteen new tests cover outcome/future-fill feature rejection, invalid values/timestamps, overlapping labels, simultaneous symbol grouping, boundary purging and non-promotional readiness. Combined ML/economics focused tests: 31 passed, zero external network attempts. Full backend validation: 2,625 passed, four explicit live/archive opt-in skips, zero external network attempts. Frontend checks earlier in this same correction run: 238 passed and production build passed; frontend code was unchanged by the ML controls.

Scikit-learn, PyTorch, XGBoost and LightGBM are not installed in the current research environment. None was installed for this feasibility step. No model weights were downloaded, no account/history was uploaded to a model service, and no signal changed. This module is experimental research governance, not integrated enforcement of the live or backtest strategy; it cannot authorize execution.

Security requirements before model fitting/inference: pin dependencies and weights with provenance; evaluate offline with network blocked; hash model, feature schema, scaler and training window; prefer a reviewed finite JSON coefficient artifact for the first linear model; bound artifact size and reject NaN/unknown fields; never deserialize remote executable model objects; keep secrets/account identifiers out of training and prompts. Any future model use is an optional offline canonical-pipeline filter, with missing/corrupt/incompatible artifacts producing an explicit blocked research result. No learned output may alter stops, lots, execution gates or risk authorization.

## Recommendation / NOT proven

**Needs more qualified data, causal opportunity labels and verified costs.** Proceed next with the canonical opportunity-recorder design and new immutable historical-service data inventory, preserving all existing safety and holdout rules. Freeze an ML protocol only when those prerequisites are met. Zero models fitted and zero ML performance trials is an honest readiness result, not a trained strategy.

No profitable strategy, positive OOS expectancy, deep-learning superiority, representative all-symbol/regime sample, complete label coverage, verified financing calendar, secure model loader, canonical ML equivalence or deployment readiness is established. The current negative baseline and all failed/blocked prerequisites remain visible.
