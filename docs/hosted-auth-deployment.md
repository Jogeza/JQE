# Hosted authentication and access deployment

The Vercel project serves a static Vite client and serverless functions. It has no MetaTrader terminal or workstation databases. Hosted market/account/research API routes therefore require a valid session and entitlement, then return `LOCAL_BACKEND_ONLY`/`UNAVAILABLE`; they never proxy an unauthenticated request to the workstation and hosted order submission is not exposed.

## Provider setup

1. Create a Supabase project and apply `supabase/migrations/20261004000100_jqe_access.sql` using the Supabase CLI or SQL editor. The migration creates the auth profile trigger, RLS policies, access snapshot, one-time trial, manual referral review, admin operations, plan catalog, and atomic AI quota. Apply `supabase/migrations/20261004000200_jqe_quota_hardening.sql` afterward; it denies zero-quota requests before insertion, rejects null features explicitly, serializes authorization with per-user access changes, and removes client table privileges beyond the required RLS reads. The base migration is already installed in production; do not rerun its non-idempotent policy creation statements.
2. In Supabase Auth, configure the production Site URL as `https://jqe.vercel.app`, enable email/password authentication and email confirmation, and allow redirects to `https://jqe.vercel.app/onboarding` and `https://jqe.vercel.app/recover`. Add only required Vercel preview origins if preview sign-in is needed.
3. Configure these Vercel variables for Production (and Preview only if needed): `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_URL`, and `SUPABASE_ANON_KEY`. The `VITE_` values are public project configuration; Supabase RLS and server-validated bearer tokens remain the authority. Never configure a service-role key in the Vercel client or these handlers.
4. Optionally set `VITE_WELTRADE_REFERRAL_URL` to the approved partner URL. All Weltrade links use this shared value; the fallback is the current configured partner URL. A click is never verification.
5. Create the first admin only after the owner verifies the account email. From the Supabase SQL editor, promote that user's UUID using `update public.jqe_profiles set role = 'admin' where id = '<verified-auth-user-uuid>';`. Do not add an admin role to signup metadata; the trigger intentionally ignores it.
6. After applying the migration and confirming the RPCs exist, set `VITE_JQE_ACCESS_SCHEMA_READY=true` for Production and redeploy. The frontend keeps signup/login/recovery submissions disabled until this flag is set; server entitlements independently enforce every protected action.

The frontend disables signup/login/recovery controls if the public Supabase configuration is absent. Vercel's protected functions return `AUTH_BACKEND_UNCONFIGURED` if server configuration is absent. Access remains denied in either case. There are no final subscription prices or payment routes; plan prices remain null and referral approval alone grants no entitlement. Admin access overrides require an expiry and the UI offers a 24-hour grant, suspension, and clearing the override.

## Hosted capability boundary

Trial entitlements grant `workspace_read`, `research_read`, and `ai_chat`; AI chat is limited by the `jqe_feature_limits` database row and consumed atomically on the server. Automated execution is absent. MT5/account/market history is deliberately unavailable on Vercel until a separate authenticated backend is deployed and audited. Do not expose the local API, terminal port, account credentials, or an order-submission route to the public internet.

## Validation

With provider configuration, validate email confirmation, password sign-in, sign-out, recovery callback, `/app` and `/admin` access checks, duplicate trial activation, UTC expiry, AI quota exhaustion, and non-admin referral/access mutations. The local frontend tests use mocked auth/RPC calls; they do not verify a real Supabase or MT5 account.
